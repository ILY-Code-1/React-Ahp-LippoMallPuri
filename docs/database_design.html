01Strategi Pemodelan NoSQL

Enerlyze menggunakan kombinasi strategi Referencing dan Embedding yang dipilih sesuai karakteristik tiap fitur aplikasi:

Referencing (normalisasi) dipakai pada entitas master yang berdiri sendiri dan sering berubah. Koleksi areas_enerlyze menyimpan user_id sebagai referensi ke users_enerlyze (penanggung jawab area), dan data_enerlyze menyimpan area_id serta created_by sebagai referensi. Pendekatan ini dipilih karena satu user dapat memegang banyak area dan satu area memiliki banyak catatan energi lintas bulan — meng-embed data tersebut akan menduplikasi informasi dan menyulitkan proses edit master User/Area.

Embedding (denormalisasi) dipakai pada koleksi ahp_results_enerlyze. Saat fitur Jalankan Analisis AHP dieksekusi, hasil perhitungan — array criteria (bobot tiap kriteria), matriks criteria_matrix (matriks gabungan narasumber), experts (narasumber final yang dipakai), dan ranking (skor prioritas tiap area) — disimpan langsung sebagai array/map di dalam satu dokumen hasil. Hasil AHP bersifat snapshot historis: sekali dihitung untuk satu bulan, nilainya tidak boleh ikut berubah walau master Area atau penilaian narasumber kemudian disunting/dihapus. Embedding menjaga laporan tetap konsisten dan membuat halaman Laporan Detail AHP cukup membaca satu dokumen.

Bobot kriteria berasal dari koleksi ahp_judgments_enerlyze (satu dokumen per narasumber, maksimal 3). Saat Run AHP, penilaian berstatus final (minimal 2) digabung dengan rata-rata geometrik; hasil gabungan dan identitas narasumbernya di-embed ke dokumen hasil, dengan penanda weight_source = "expert_pairwise". Hasil lama (sebelum fitur narasumber) tidak memiliki weight_source dan experts; bobotnya dibentuk dari rank kriteria.

Contoh konkret: dokumen ahp_results_enerlyze/2026-05 menyimpan ahp_id "AHP-2026-05", weight_source "expert_pairwise", experts berisi 2 narasumber, objek consistency berisi cr = 0.0022, serta array ranking yang sudah memuat area_name "2F" (skor 0.2215, peringkat 1) hasil snapshot — tanpa perlu join ke areas_enerlyze maupun ahp_judgments_enerlyze.

Catatan teknis (nested array): Firestore tidak mendukung nested array (array of arrays). Matriks pairwise kriteria 4×4 karena itu tidak disimpan sebagai number[][], melainkan diserialisasi ke bentuk map-of-rows { rows: [{ cells: [...] }] } (helper serializeMatrix() pada src/lib/ahp.js), lalu dideserialisasi kembali ke matriks 2D dengan deserializeMatrix() saat ditampilkan di halaman Laporan Detail AHP. Hal yang sama berlaku untuk matrix pada ahp_judgments_enerlyze, sedangkan pairs disimpan sebagai array of map datar { a, b, value }.

02Struktur Koleksi

Tujuh koleksi root pada Firestore. Setiap koleksi diberi sufiks _enerlyze sesuai konvensi proyek.

  • users_enerlyze  — doc ID: auto (mis. u_8Kx2Lp)
    • name string
    • email string
    • password string — format salt:hash (PBKDF2)
    • role string — "admin" | "staff"
    • created_at timestamp
    • updated_at timestamp
  • areas_enerlyze  — doc ID: auto (mis. ar_L1Gf9)
    • name string — mis. "Lantai 1"
    • description string — mis. "Lobby, Food Court"
    • user_id string · ref → users_enerlyze
    • created_at timestamp
    • updated_at timestamp
  • criteria_enerlyze  — doc ID = key (energy, cost, duration, maintenance) · LEGACY: tidak lagi dibaca aplikasi; empat kriteria kini tetap di kode (src/constants/criteria.js)
    • key string — identitas stabil kriteria
    • code string — KE / BL / DO / FM
    • name string
    • rank number — 1..4 (unik) · LEGACY, tidak lagi dipakai untuk bobot
  • data_enerlyze  — doc ID: auto (mis. dt_Apr01)
    • area_id string · ref → areas_enerlyze
    • month string — format YYYY-MM
    • energy number — kWh
    • energy_area_m2 number — luas area (m²)
    • cost number — Rupiah
    • duration number — jam operasional
    • maintenance number — frekuensi/bulan
    • created_by string · ref → users_enerlyze
    • created_at / updated_at timestamp
  • ahp_judgments_enerlyze  — doc ID: auto · satu dokumen per narasumber, maksimal 3
    • expert_name string · expert_position string — nama & jabatan narasumber (wajib)
    • criteria_codes array<string> — urutan baris/kolom matriks: ["KE","BL","DO","FM"]
    • pairs array<map> — 6 × { a, b, value }; value skala Saaty 1/9..9 (n bila a lebih penting, 1/n bila b lebih penting)
    • matrix map — matriks resiprokal 4×4 bentuk { rows: [{ cells: [...] }] }
    • weights array<number> · lambda_max · ci · cr number — hasil hitung dari pairs
    • status string — "draft" | "final" (final hanya bila cr < 0,1)
    • created_by string — nama/email admin · created_at / updated_at timestamp
  • ahp_results_enerlyze  — doc ID = month key (mis. 2026-05)
    • month string · ahp_id string — mis. "AHP-2026-05"
    • weight_source string — "expert_pairwise"; tidak ada pada hasil lama (bobot dari rank)
    • experts array<map> — embedded snapshot: {id, expert_name, expert_position, cr} narasumber final yang dipakai
    • criteria array<map> — embedded: {key, code, name, weight} (hasil lama juga memuat rank)
    • criteria_matrix map — matriks pairwise gabungan 4×4 (rata-rata geometrik) bentuk { rows: [{ cells: [...] }] } (Firestore-safe, bukan nested array)
    • criteria_weights array<number>
    • consistency map — {lambdaMax, ci, cr, isConsistent}
    • ranking array<map> — embedded: {area_id, area_name, area_description, score, breakdown, rank} (rank = peringkat area)
    • created_by string · created_at timestamp
  • notifications_enerlyze  — doc ID: auto
    • user_id string · ref → users_enerlyze
    • type string — "missing-data" | "ahp-pending"
    • message string
    • link string — rute tujuan saat notifikasi diklik
    • created_at timestamp

Relasi antar koleksi diwujudkan lewat field referensi ID: areas_enerlyze.user_id → users_enerlyze, data_enerlyze.area_id → areas_enerlyze, data_enerlyze.created_by & notifications_enerlyze.user_id → users_enerlyze, ahp_results_enerlyze.experts[].id → ahp_judgments_enerlyze (snapshot; dokumen narasumber dapat dihapus kemudian tanpa mengubah hasil).

Catatan integritas: Firestore tidak menegakkan foreign key secara native. Integritas referensial dijaga di lapisan aplikasi — mis. GUARD user yang masih memegang area tidak dapat dihapus, area yang masih memiliki catatan data_enerlyze tidak dapat dihapus, dan satu pasangan (area + bulan) hanya boleh memiliki satu dokumen data_enerlyze. Untuk ahp_judgments_enerlyze: maksimal 3 dokumen narasumber (draft + final), status final hanya dapat disimpan bila cr < 0,1, dan Run AHP ditolak bila narasumber final kurang dari 2 atau CR gabungan ≥ 0,1.
